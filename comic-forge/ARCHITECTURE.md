# 漫画工作台 · 落地架构

把「点子 → 成品 PDF」这条线真正跑起来，核心不是再写一个大插件，而是**用一条约定好的目录结构 + 一个工作台界面，把现有能力串起来**。

参考项目怎么用：
- `ai-manju-skills` → 提供**文本流水线**的提示词模板（点子→企划→分集→分镜），我们照它的产出结构定义中间格式。
- `dsh-image-gen` / ComfyUI → **图像生成后端**，工作台只管发请求、收图，不绑定具体模型。
- `DiffSensei` → **角色一致性**的思路来源（参考图 + 角色嵌入 + 分镜布局），落地时简化成「角色参考图 + 角色锁提示词」。
- `ComicUI / ComfyUI 漫画节点` → 排版、分格、贴对话框这半可以复用现成节点，不必自己造。

---

## 1. 六阶段流水线与产出物

每一阶段读写固定目录，阶段之间靠**文件**解耦，任何一环都能换工具重跑。

| 阶段 | 输入 | 产出物（文件） | 用到的能力 |
| --- | --- | --- | --- |
| ① 故事大纲 | 一句点子 | `story/outline.md`（logline + 三幕） | LLM / `ai-manju-skills` 企划模板 |
| ② 人物设定卡 | 大纲 | `characters/<角色>.md` + `characters/ref/<角色>-{正,侧,背}.png` | LLM 写设定 + image-gen 生成三视图 |
| ③ 分镜脚本 | 大纲 + 设定卡 | `storyboard/page-<n>.json`（格子/镜头/台词） | LLM 分镜模板，输出结构化 JSON |
| ④ 批量生图 | 分镜 JSON + 角色参考图 | `panels/<page>-<格>.png` | image-gen / ComfyUI，带角色锁 |
| ⑤ 排版 · 对话框 | panels 图片 + 台词 | `pages/page-<n>.html`（可渲染） | 排版引擎 / ComfyUI 漫画节点 |
| ⑥ 导出 | 排版结果 | `export/夜行电车-01.pdf`、`-长图.png` | HTML→PDF（Playwright）、图片拼接 |

**关键约定：中间格式固定，工具可替换。** 只要 ③ 产出 `page-<n>.json`，④ 用 dsh-image-gen 还是 ComfyUI 都行；只要 ⑤ 产出 HTML 页面，⑥ 导出就是一条命令。

## 2. 项目目录（一套漫画 = 一个文件夹）

```
夜行电车/
  comic.json                 # 项目元信息 + 流水线状态（哪阶段完成了）
  story/outline.md
  characters/
    林晚.md                  # 设定卡：外貌/服装/性格 + 一致性提示词片段
    ref/林晚-front.png …     # 角色三视图（一致性基准）
  storyboard/
    page-1.json …            # 每页：格子数组，每格含 camera/desc/dialogue/panel_hint
  panels/                    # 逐格生成图，文件名 = 页-格号
  pages/                     # 排版后的页面（HTML 或 PNG）
  export/                    # PDF / 长图成品
```

`comic.json` 记录进度，工作台首页的六阶段状态条就读它：

```json
{
  "title": "夜行电车", "episode": 1,
  "stage": { "outline":"done", "characters":"done", "storyboard":"done",
             "render":"doing:18/24", "layout":"todo", "export":"todo" },
  "style": { "preset":"黑白网屏", "consistency":0.8, "engine":"dsh-image-gen" }
}
```

## 3. 角色一致性怎么落地（最关键的一环）

纯文字提示词撑不住跨格一致性，必须「图 + 词」双保险：

1. **角色三视图**（阶段 ②）：每个角色生成 正/侧/背 三张基准图，存进 `characters/ref/`。
2. **角色锁**（阶段 ④）：生成每一格时，把该格出场角色的参考图作为 image-to-image / 角色参考输入，并把角色卡里的「一致性提示词片段」拼进 prompt：
   `[角色:林晚] 齐肩黑发，列车员制服，左眉一道浅疤`。
3. **一致性强度**：一个 0–1 滑块，映射到参考图权重 / denoise 强度。调高 → 更像参考图但构图变僵；调低 → 更自由但容易漂移。
4. **漂移检测**：每格生成后，和参考图做一次相似度比对（人脸/整体嵌入），低于阈值就标记「漂移」，提示重试——这正是原型里格子 19 那个红标。

有 GPU / 本地 ComfyUI 时，把 ④ 换成 ComfyUI 的角色参考工作流即可，接口不变。

---

## 4. 对话框与排版（阶段 ⑤）

推荐**HTML/CSS 做排版层**，而不是把气泡画死进图片里：

- 每页一个 HTML，格子用 CSS Grid 摆（原型 `layout.html` 里那套 `.page` 网格就是它）。
- 台词从 `page-<n>.json` 读进来，气泡是绝对定位的 DOM，可拖、可换样式（对话/思考/旁白/呼喊），文字永远清晰、可改。
- 好处：改台词不用重生成图；导出时 HTML→PDF 矢量文字不糊；「气泡自动避让角色」用一个遮挡检测的小脚本就能做。

需要像素级手绘气泡效果时，再走 ComfyUI 漫画节点合成，HTML 排版作为默认路径。

---

## 5. 导出（阶段 ⑥）

- **PDF**：用无头浏览器（Playwright/Chromium）把 `pages/page-<n>.html` 按 300 DPI 打印成 PDF，矢量文字、可加出血边距。
- **长图**：把各页 PNG 竖向拼接（多页连播，适合手机阅读）。
- **分页 PNG**：平台投稿用，一页一张。

三条都是导出器里的不同 preset，读同一份排版结果。

---

## 6. 和 DSH 的接法（两条路）

**A. 当 Skill 用（最快，推荐先做）**
把上面流程写成一个 Skill：喂一句点子，它按 ①→③ 生成大纲/设定卡/分镜 JSON，再调用 `dsh-image-gen` 逐格生图（带角色锁），最后产出排版页并导出。适合「一句话出一话」的自动化。

**B. 当工作台用（本原型）**
像本原型这样，人机协作：每阶段可视、可改、可重跑单格。LLM 出草稿，人把关；生成失败的单格点重试。适合对质量有要求、要反复调的连载。

两条路共用同一套目录和中间格式，可以先 B 起步，把跑通的阶段逐步交给 A 自动化。

---

## 7. 建议的落地顺序

1. **先定中间格式**：把 `page-<n>.json` 的字段和角色卡结构钉死（本原型的分镜格就是它的可视化）。
2. **跑通 ④ 单格生图 + 角色锁**：这是技术风险最高的一环，先用 dsh-image-gen 手动验证「同一角色跨 5 格不漂」。
3. **接 ⑤⑥**：HTML 排版 + 导出 PDF，纯工程，风险低。
4. **补 ①②③ 的 LLM 模板**：照 `ai-manju-skills` 改，输出对齐第 1 步的格式。
5. **最后做漂移检测、批量队列、滑块**：锦上添花。

---

## 8. 本原型三屏对应关系

| 原型文件 | 对应阶段 | 里面的真实信息 |
| --- | --- | --- |
| `pipeline.html` | 总览 ①–⑥ | 六阶段状态条 + 每阶段产出缩影 + 下一步提示 |
| `storyboard.html` | ③ 分镜 + ④ 批量生图 | 分镜格（镜头/描述/台词）+ 角色锁/一致性滑块/队列/提示词模板 |
| `layout.html` | ⑤ 排版 + ⑥ 导出 | 可视化漫画页（真气泡）+ 布局模板 + 气泡工具 + PDF/长图导出 |

> 原型里的图均为占位示意，接上真实 image-gen 后端后，格子图与页面缩略会换成实际生成结果。
